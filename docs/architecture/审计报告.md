# SelfAgent 当前架构审计报告

审计日期：2026-11-16。

## 已确认边界与入口

| 项目 | 真实入口 | 运行方式 | 配置/数据归属 |
|---|---|---|---|
| 工作台 | `workbench/machine-dashboard-server/src/server.py` | Python HTTP，默认 `18888` | 用户级 `LocalWorkbench`；日志、SQLite、PID 由工作台配置提供 |
| machine-control | `Tools/machine-control/server/control_center/server.py`、`control_mcp/server.py` | 中央 HTTP、MCP；默认中心端口 `18765` | `Tools/machine-control/data`、`logs`；Worker 通过 HTTP 协议接入 |
| AiAgent | `AiAgent/AiProject/Codes/Agents/OpenAiAgent/codex_agent/cli.py`、`openai_gateway.py` | CLI、本地 `/v1` 网关；默认 `8765` | 独立 `pyproject.toml`/`uv.lock`；OAuth 路径由 `CODEX_TOKEN_PATH` 控制 |

工作台通过 launchers 以子进程调用机器控制、Worker、调度器和 Agent；独立项目不应导入工作台 View、路由或数据库。代码检查工具保持独立，调度器通过 CLI/配置调用它。

## 依赖与存储事实

- Python import：工作台 `server.py` 当前仍设置 `sys.path`；OpenAiAgent 的 Demo 和测试存在路径注入；machine-control 通过 server/shared 的运行路径组织模块。
- HTTP：浏览器→工作台 View；工作台→外部启动器；Worker↔中央服务；Agent 网关→Codex 上游。
- 子进程：工作台 ProcessManager/launchers 负责启动、状态和停止；端口、PID 和孤儿进程处理仍需逐项验收。
- 文件：工作台用户配置和日志已由 `core.settings` 集中计算；machine-control 仍有仓库内 `data/`、`logs/`；代码检查报告位于其 `data/`。
- 数据库：工作台 `core.storage` 使用 SQLite WAL 和兼容式字段迁移；`SqliteDB` 复用连接。迁移异常目前过宽捕获，事务/备份/恢复尚未形成版本化流程。
- 环境：OpenAiAgent 有独立 Conda/pyproject 文档和 `uv.lock`；machine-control 现有独立 `pyproject.toml` 与 `uv.lock`，根 `requirements.txt` 不能作为三个项目共享环境的证明。

## 风险清单

1. 工作台 `storage.PID_PATH` 指向源码树 `data/`，与“运行产物不得写入源码目录”冲突。
2. SQLite 字段迁移捕获所有 `OperationalError`，可能掩盖锁、磁盘或 SQL 错误。
3. 根依赖与三个项目的独立发布/冲突关系尚未决策。
4. `Tools/local_codex` 与工作台 local_codex 的真实职责和发布源未核对。
5. machine-control `client` 与 `packages/central-client` 存在源码/打包副本，需确认唯一发布源。
6. 完整的三项目启动、迁移备份恢复、关键页面流程和关闭后无遗留进程尚未全部验证。

- 正式运行是否允许仓库内 machine-control `data/` 和 `logs/`，还是迁移到用户级输出根目录。
- 是否保留代码检查对 OpenAiAgent 本地配置的回退读取。
- Windows 目标 Python 版本及 machine-control/AiAgent 的锁定策略。
