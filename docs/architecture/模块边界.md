# SelfAgent-模块边界

## 1. 运行单元

| 模块 | 入口/边界 | 允许的依赖方向 |
| --- | --- | --- |
| 工作台服务端 | `workbench/machine-dashboard-server/src/server.py` | 页面托管、认证授权、服务端 View、调度、数据和服务端进程编排 |
| 工作台客户机 | `workbench/machine-dashboard-client/src/local_agent.py` | 浏览器所在机器的本地目录、中央客户端和本地 Codex；仅监听回环地址 |
| 机器控制 | `Tools/machine-control/server`、`client`、`shared` | 中央服务与 Worker 通过既定协议通信 |
| 代码检查 | `workbench/machine-dashboard-server/tools/code-review-agent/code_review/cli.py` | 工作台内部工具，由调度器经 CLI/进程协议调用；运行数据进入用户级工作台目录 |
| 智能体 | `AiAgent/AiProject/Codes/Agents/OpenAiAgent` | 自主管理 OAuth、CLI 和本地网关 |
| 技能 | `skills/<name>/SKILL.md` | 提供开发流程约束，不作为运行时业务依赖 |

## 2. 稳定入口和默认值

| 名称 | 当前值或位置 | 用途 |
| --- | --- | --- |
| 客户机配置 | `%LOCALAPPDATA%/LocalWorkbench/config/settings.json` | 每台客户机独立保存本地存储目录；默认 `%LOCALAPPDATA%/LocalWorkbench/client/storage` |
| 服务端配置 | `%LOCALAPPDATA%/LocalWorkbench/config/server-settings.json` | 服务端日志、输出和业务配置，不覆盖客户机配置 |
| 工作台 | `MACHINE_DASHBOARD_HOST`、`MACHINE_DASHBOARD_PORT=18888` | 本地 HTTP 服务 |
| 控制中心 | `MACHINE_CONTROL_PORT=18765`；未显式传 `--store` 时使用用户级 MachineControl 数据目录 | 机器控制服务 |
| 智能体网关 | `CODEX_GATEWAY_PORT=8765` | 本地 `/v1` 模型网关 |
| 本地接入服务 | `WORKBENCH_LOCAL_AGENT_PORT=18991` | 客户机 Local Agent，仅绑定 `127.0.0.1` |
| 本地 Codex | `CODEX_APP_SERVER_PORT=4500` | 由客户机 Local Agent 启动的本地服务 |
| 工作台会话 | `LOCAL_WORKBENCH_START_TIMESTAMP` | 日志会话标识 |

实际默认值以目标代码为准；改变端口、路径或环境变量时必须同步文档和调用方。

## 3. 接口契约

- 工作台页面：`web/pages` + `web/assets/js/pages` 通过 HTTP JSON 调用 `src/view`；成功响应通常包含 `ok: true`，失败响应包含 `ok: false` 和 `error`。
- Jenkins 管理：工作台用户级 SQLite 保存 IP、协议和端口；工作台通过 HTTP 检测 Jenkins 标识，并读取中央控制服务的 Worker 状态。探测失败不改变配置，中央服务不可用时连接状态为未知。管理员可向已登记的 Jenkins 自助注册接口提交账号信息，密码不持久化；注册不可用时返回实例级结果。权限管理凭据从服务器用户级 server-settings.json 读取（环境变量优先），工作台经 Jenkins Script Console 访问全局矩阵，不支持的授权策略和并发冲突须拒绝写入。
- KOA：工作台的 `/pages/jenkins-koa.html` 页面经受 `manage` 权限保护的 `/api/jenkins/last-completed` 查询一个已登记实例的单个任务。工作台以匿名 GET 访问 Jenkins，不传递凭据；拒绝访问、无构建及连接失败时返回提示。
- 工作台进程：业务接口请求稳定服务名；ProcessManager 调用对应启动器处理命令、环境、PID 和状态。
- 插件工具：使用 `tool_id + args`，本地进程入口接收 JSON 参数，退出码 0 表示成功，标准输出作为结果。
- 代码检查：`python -m code_review.cli` 由配置驱动，检查通过才更新成功基线。
- 智能体：对外提供本地 `/v1` 接口；工作台不读取或返回令牌。

## 4. 归属判断

1. 服务端页面托管、设置 API（服务端配置）、调度、进程状态和工作台接口归 `workbench/machine-dashboard-server`；浏览器所在机器的路径、中央客户端和本地 Codex 归 `workbench/machine-dashboard-client`。
2. 中央控制、Worker、机器控制协议归 `Tools/machine-control`。
3. Unity 增量检查、规则加载和报告归工作台；实现已位于 `workbench/machine-dashboard-server/tools/code-review-agent`。
4. OAuth、模型网关和 Agent 工具调用归 OpenAiAgent。
5. 可复用开发流程归 `skills`；技能文件不应写入项目运行时路径。

不确定归属时先记录为待确认，查清入口和调用方后再移动代码。
## 代码检查归属

代码检查业务属于工作台能力，实现位于 `workbench/machine-dashboard-server/tools/code-review-agent`，工作台通过
`src/schedulers/code_review_scheduler.py` 和 `run_task.py` 的 CLI/进程边界调用它；不得把它写入三个独立项目的边界清单。
