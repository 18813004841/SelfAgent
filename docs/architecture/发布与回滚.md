# 发布与回滚

当前状态：流程定义，尚无完整发布演练证据。不得据本文宣布可发布。

## 发布单位与兼容

工作台、AiAgent、machine-control 分别发布源码/构建产物与自己的依赖声明。
发布记录必须包含 Git commit、Python 版本、锁文件摘要、配置版本、数据版本、
客户端/服务端兼容组合及验证报告。工作台不携带其他项目的数据库或本地凭据。
machine-control 客户端由本项目打包脚本生成，必须用对应中央服务版本执行任务回归。
新增协议字段先保持旧客户端可用；删除字段或变更语义需新协议版本及兼容窗口。

## 发布前门禁

1. 从干净目录安装每项目声明和锁定依赖；禁止复用开发环境充当重建证据。
2. 执行架构、依赖、存储、迁移、HTTP、进程和 Web 检查；保留退出码和报告。
3. 完成真实浏览器关键流程、中央服务/Worker 任务、超时和失败流程。
4. 在隔离目录恢复一次数据备份；校验文件摘要、数据库完整性与业务记录数量。
5. 验证指定配置目录中的日志及运行产物，停止后确认本次进程和监听端口释放。
6. 确认完整验收矩阵的必需项已通过。任一未验证流程（包括干净机器安装、真实浏览器/跨主机业务、数据迁移和回滚演练）均阻止正式发布。

## 部署和回滚操作

本机接入客户端 `workbench-machine-dashboard-client` 从 `VERSION` 发布版本，当前正式版本为 `1.0.0`。发布前重新构建 `workbench-machine-dashboard-client.zip`，确认 ZIP 内 `VERSION` 与 `pyproject.toml` 一致；工作台和 Local Agent 分别通过 `/api/local-agent/version` 提供发布版本与已安装版本。设置页下载 ZIP 后可运行包内 `update-client.ps1`，升级器先校验入口和版本、停止归属明确的 Local Agent、保留 `.previous` 后切换；切换失败恢复旧目录。客户端配置、日志和任务数据不随包覆盖。

部署前记录服务版本、启动参数和数据路径，停止写入并停止拥有句柄的服务；
SQLite 使用数据库 backup API，不能在写入中仅复制主文件而遗漏 WAL。
备份放到独立目录并做完整性校验，保存旧配置和旧应用目录。
新版本使用新目录和新虚拟环境启动，先在数据副本演练迁移，再切换正式配置。
旧数据和旧环境在回滚窗口内保留，不用新安装覆盖旧环境。

回滚时停止本次新版本进程，保留故障现场和新增数据副本。
若数据版本向后兼容，可让旧应用使用当前数据；否则恢复发布前备份到新的空目录，
切换旧配置指向恢复目录，再启动旧应用。明确记录备份后新增数据的补录方案，
禁止静默覆盖正式数据或用 Git reset 回滚用户文件。
回滚后重新验证关键业务、日志、记录一致性和退出清理；保留结果后才关闭发布事件。
