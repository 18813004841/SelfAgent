# 架构治理范围与排除项

## 纳入范围

| 运行单元 | 纳入内容 | 依据 |
| --- | --- | --- |
| 工作台 | HTTP 服务、View、页面、ProcessManager、Launchers、调度、配置和存储 | `workbench/machine-dashboard-server/src/server.py`、子目录规则 |
| 机器控制 | 中央服务、Worker、共享模型、MCP、客户端打包 | `Tools/machine-control/README.md` 与现有入口 |
| 代码检查 | CLI、增量管线、规则加载、模型客户端、调度器 | `Tools/code-review-agent/README.md` 与 `code_review/` |
| OpenAI Agent | CLI、OAuth、网关、模型适配和测试 | `AiAgent/.../OpenAiAgent/README.md` 与 `pyproject.toml` |
| 仓库技能 | `skills/*/SKILL.md` 的发现与适用范围 | 根 `AGENTS.md` 与现有技能 |

## 暂不改造

- `AiAgent/.../Codes/Demos`：仅登记为示例，除非某个示例被提升为产品运行单元。
- `_dbcheck`、`_wbcheck`、`tmp-local`、`logs`、各模块 `logs`：运行检查、缓存和历史产物，不纳入源码架构迁移。
- 当前未提交的业务代码和新增目录：本次只审计其架构影响，不回滚、不重写、不替用户决定合并。
- 根目录空 `src/`：暂不作为公共代码层，等待依赖和复用方审计。

## 范围决策

本轮治理目标是建立可执行的边界与检查入口，不要求一次性消除所有历史技术债。历史实现与目标规则冲突时，先记录事实、影响和迁移方案，再按单独任务改造。
