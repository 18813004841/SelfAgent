# 目标架构与迁移映射

## 目标目录树

```text
workbench/machine-dashboard-server/
  src/{server.py,view,services,process_manager,core,adapters}
  web/{pages,assets}  config/{.env.example,templates}  scripts/ tests/ docs/
AiAgent/AiProject/Codes/Agents/OpenAiAgent/
  codex_agent/ tests/ pyproject.toml uv.lock environment.yml docs/
Tools/machine-control/
  server/ client/ shared/ scripts/ tests/ config/ data/ logs/
docs/architecture/  skills/ scripts/
```

`src/` 根目录保持非公共层；跨项目调用只经 HTTP、CLI、协议或工作台 launcher。三个项目分别拥有源码、依赖、配置模板、测试和运行数据。

## 迁移映射

| 当前内容 | 目标归属 | 迁移策略 | 验收 |
|---|---|---|---|
| 根 `requirements.txt` | 工作台或拆分为项目清单 | 先生成实际 import/命令矩阵，再决定保留兼容清单 | 新环境安装和入口 smoke test |
| 工作台 `src/core/settings.py`、`storage.py` | 工作台基础设施层 | 保持兼容 API，增加版本迁移、备份和输出根 | 隔离 `LOCALAPPDATA` 启动、DB 完整性检查 |
| 工作台 `server.py` legacy | `services`/`view`/`adapters` | 按接口逐段迁移，保留旧路由兼容窗口 | 页面链路和 API 回归 |
| machine-control `server/client/shared` | machine-control 独立项目 | 不复制到工作台；launcher 只传协议参数 | 中心、Worker、MCP 各自 smoke test |
| OpenAiAgent CLI/网关 | AiAgent 独立项目 | 保持 pyproject/uv.lock；工作台只调用网关/CLI | 隔离端口、无真实 token 的网关验证 |
| 仓库日志、DB、缓存、zip | 配置指定的 output/data/logs | 先忽略，再迁移已跟踪项并保留本地文件 | Git 检查与关闭后产物检查 |

## 分批实施与回滚

1. 审计批：冻结事实、入口、依赖和风险；回滚为删除新增文档。
2. 治理批：忽略规则、检查脚本、配置/输出契约；回滚为恢复规则文件。
3. 数据批：新增版本化迁移、备份、恢复和隔离目录；迁移前复制数据库并可切回旧路径。
4. 边界批：按模块迁移 import、launcher 和页面契约；每个入口保留兼容窗口。
5. 验收批：三项目隔离启动、关键接口/流程、关闭清理和 Git 检查；失败时保留 Goal 进行中。

## 代码检查 CLI 迁移门槛

工作台侧已新增 `src/integrations/code_review_cli.py`，定义显式子进程和 JSON 结果边界。
当前 scheduler 暂保留旧 Python 承接接口，因为它提供实时进度、取消回调和数据库状态写入。
只有 CLI 协议补齐进度事件、取消信号、超时和退出码映射后，才切换默认路径；切换前后
必须通过代码检查页面回归和取消任务验收。
