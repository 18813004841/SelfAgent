# SelfAgent 架构持续维护

## 维护责任

| 内容 | 维护位置 | 触发条件 |
| --- | --- | --- |
| 模块关系和边界 | `docs/architecture/架构总览.md`、`模块边界.md` | 新增模块、改变职责或跨模块调用 |
| 入口和启动方式 | `docs/architecture/入口清单.md` | 新增 CLI、HTTP、MCP、启动脚本或端口 |
| 依赖关系 | `docs/architecture/依赖矩阵.md` | 新增 import、HTTP、子进程、文件或数据库依赖 |
| 开发约束 | 根 `AGENTS.md` 和目标模块 `AGENTS.md` | 新增稳定约定或发现规则冲突 |
| 架构流程 | `skills/selfagent-architecture/SKILL.md` | 架构维护步骤、路由或验收方式变化 |
| 技术债和验证 | `docs/architecture/验证记录.md` | 检查失败、运行限制、迁移延期或完成验证 |

## 固定检查

在架构变更、跨模块变更和交付前执行：

```powershell
python scripts/check_architecture.py
python -m py_compile scripts/check_architecture.py
```

修改代码检查管线时增加：

```powershell
python scripts/run_code_review_validation.py
```

工作台页面或 View 变更还必须执行工作台自身规则和 `workbench-ui-flow` 的真实链路验证。

## 例外机制

暂时无法遵守边界时，在对应架构文档登记：路径、例外原因、影响、替代措施、责任人和复审条件。例外不能只写在提交说明或聊天记录中。架构检查允许报告问题但不自动修改业务代码；是否阻断交付由变更审查决定。

## 技术债格式

```markdown
- [ ] 路径/模块：问题与当前影响；依据：代码或日志位置；责任人：待定；复审条件：具体事件。
```

完成技术债后必须删除或改为验证记录，避免“已完成”和“仍存在”同时出现。

## 维护边界

架构检查不替代单元测试、接口测试、进程测试或安全审查。检查通过只表示已登记文档、链接和已声明边界通过；动态导入、运行时配置、外部服务和模型上游仍需按模块单独验证。
